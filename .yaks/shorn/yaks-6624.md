Distinct axis from yaks-a2ca (which evals yaks itself): make the yaks skill/tool STRUCTURE encourage building AND continuously using real eval tooling for whatever project the agent works on. Motivating finding (honest, self-implicating): we built toque (the agent-facing 'control-cli' for the yaks TUI) but NO skill/AGENTS guidance tells an agent to use it to SEE output before declaring a TUI change done — so the habit decayed to a doc-gen/CLI utility after the first runs. TUI behavior is still validated via insta snapshots, but the 'agent looks at the real artifact' discipline lives nowhere. pstack addresses exactly this via create-verification-skill (build the lever), maintain-verification-skill (daily anti-drift, 'oncall rotation'), control-cli/control-ui (domain levers; toque==control-cli, sightmap==control-ui), the prove-it-works principle, and the tech-stack thesis (make the app controllable — input+state, not just screenshots — or agents thrash). pstack ENFORCES via a sticky router + per-turn principle re-read + adversarial review subagents; yaks refuses that machinery. yaks-native placement of the same responsibility: the SHEAR is the 'declaring done' gate (doctor --strict = mechanized bullshit-caller, strengthen per 79a9); yaks ask = the 'go on walkabout to build eval tooling' escalation (needs-block makes it unbypassable, inbox makes it visible); the lever's ABSENCE becomes a tracked yak; per-repo context (7cd1) names what 'verify' concretely means. Nothing forces a model to look (true in pstack too) — yaks makes the honest path cheap+first-class, the dishonest path detectable, and the tooling gap a visible queue item.

REFINEMENT (Joel): unify the thread under an EVIDENCE CONTRACT. (1) Invariant: every shorn yak carries evidence — but generalize beyond 'correctness' to 'evidence appropriate to the yak's kind that its outcome was achieved and seen' (research=the finding, decision=the rationale; dead exempt). Structured/attributed evidence makes the yak a substrate for 'validating the validation' (queryable: prose vs rerunnable-command vs artifact). (2) The coordinator states WHAT IT WILL ACCEPT as evidence AT CLAIM TIME (the same claim-commit that licks the cookie), as a definition-of-done — not post-hoc. Forcing function: if you can't articulate acceptable evidence, the lever is missing -> that IS the yaks-ask walkabout trigger. Unifies 139b (verify-or-ask) + c3b1 (levers) + 79a9 (backstop). (3) Role not actor: authored by the coordinator when there is one, else by the working agent itself (solo mode still writes its own definition-of-done first). (4) Layering matches views/config: per-repo config = baseline contract per change-type; coordinator specializes per-yak. (5) Shape: contract as an 'accept:' note-convention first, graduate to a frontmatter field per our convention->tool rule; evidence via notes/attachments; doctor --strict checks evidence exists AND post-dates the contract. GAP found: no CLI 'attach' (herd.attach + TUI A/O only) — agents can only note an artifact path; a 'yaks attach' CLI would make evidence-as-artifact first-class for CLI agents.
