Factor the yak-reference primitive out of the TUI into a shared resolver that every other child in this herd builds on.

Today the only reference logic is scan_body_links in src/tui/detail.rs: it scans a body line, matches bare prefix-1234 tokens (and [[wiki]] via strip_brackets), and links a token ONLY if it equals a real on-disk id (validation-based, prefix-agnostic). Right strategy, wrong home: it lives in the TUI and knows only the local herd id set.

Scope:
- Lift resolution into the facade (herd.rs/store.rs) as the single source of truth for CLI + TUI + rename: resolve(token, id_set) -> Option<YakRef>.
- Pin the reference grammar: canonical full form prefix-1234; [[prefix-1234]] wiki alias; RESERVE a herd-qualified form for cross-herd refs (see yaksrs-15f7). Decide bare-hex 1234 policy (leaning: not auto-linked; skills nudge full form).
- Make the id set a parameter so it can widen from one herd to a friend-set (yaksrs-15f7) without touching callers.
- Add a CLI surface to list/validate references (e.g. yaks refs <id> / a link-check) so integrity is inspectable outside the TUI.

Blocks c2c5 (render), 0af1/7a92 (rename), 15f7 (federation).
