Surfaced by dogfooding the prefix migration (yaks-7a92): 6 real references of the form `yaksrs-XXXX.` (id at the end of a sentence) were NOT rewritten, because the refs tokenizer treats "." as a ref char (to keep legacy dotted ids like yak-a1b2.1 whole). So a sentence-ending period is absorbed into the token — `yaksrs-688d.` != the id `yaksrs-688d` — and the token fails to match.

This also affects DETECTION: such a mention would not link in the TUI detail pane either (detail.rs scan_body_links has the same tokenizer).

Fix: trim trailing "." from a scanned token before matching (real ids never end in a dot; dotted legacy ids keep their interior dots). Do it in one shared tokenizer (refs::token_at) consumed by refs::scan, refs::rewrite, AND detail.rs, re-emitting the trimmed dots as literal text. Then repair the 6 already-migrated stragglers.

FIXED. Root cause: the refs tokenizer treated "." as a ref char (to keep legacy dotted ids whole), so a sentence-ending period was absorbed into the token and `yaksrs-688d.` failed to match the id. Introduced shared refs::token_at (maximal ref run, then trim trailing dots, re-emitting them as literals) now consumed by refs::scan, refs::rewrite, AND detail.rs scan_body_links — so detection, rewrite, and the TUI all agree on boundaries. 3 regression tests (scan trailing period, rewrite preserves period, interior dot kept). Repaired the 6 already-migrated stragglers (yaks-7a92/a2a4/c725/b716/e741/fe00). Verified: dangling sweep across all 165 yaks clean; the missed mentions now resolve. 191 lib tests, warning-free.
