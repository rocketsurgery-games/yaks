yaks log (yaks-c9ee) surfaces notes only; state changes (shave/shorn/regrow) are not individually timestamped, since status is implicit in the directory. To include transitions in the activity log, record a timestamped transition entry when move_task runs (an appended marker or a sidecar), then have herd::log merge notes + transitions. Keep it cheap and files-authoritative.

Assessment (pre-compact): self-contained, medium value, no urgency. Makes 'yaks log' a full activity record (when shaved/shorn, not just notes) — useful for provenance and as an fe5a eval signal. Design cautions: stay files-authoritative (status = the dir); a body marker is simplest but clutters, a frontmatter 'transitions:' list is structured but grows — choose deliberately. KEY: in TEAM mode git already records transition timestamps (the commit that moved the file; 'yaks commits' finds it via file-follow), so 8265's real value is SOLO mode + a unified in-log view. Partly redundant with git in team mode.
