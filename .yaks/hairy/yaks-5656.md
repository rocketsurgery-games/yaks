Trigger yak-id completion while editing a description/comment, so ids do not have to be copy-pasted or memorized (the original driver behind yaks-688d).

Design sketch: reuse the existing FuzzyPick overlay (ranked id/title search, single-line query) with a new FuzzyAction::InsertRef; bind a trigger key in the multiline editor to open it, seeded from the word under the cursor; on commit, insert the FULL prefix-1234 id at the cursor (feed chars through edtui the Insert handler so cursor + undo behave). Full-form insertion matters because validation-based linking keys off the complete id.

NOTE the real cost: overlays are a single enum slot (Overlay::…), so opening the picker from inside Overlay::Edit needs overlay NESTING (or a stack) to return to the editor afterward — that architectural bit is the bulk of the work, which is why this is split out of yaks-c2c5 rather than folded in.

Split from yaks-c2c5. Detection/highlight/follow already shipped there; the resolver (yaks-0187) provides the candidate set + full-form ids.
